## Hardening added in this review

- `ci/audit-source.sh` enforces repository-wide native-only source policy,
  expected workflow file inventory and absence of JavaScript invocation.
- `ci/native-cases.txt` is an explicit, reviewable twelve-scenario manifest.
- `ci/verify-native.sh` requires an actual pinned Oreslang executable,
  `--build-info`, exact tracked clean source, per-case bounded checking
  and execution, exact stdout, case coverage and per-file Git blob SHA logs.
- CI checkout is pinned to `github.event.pull_request.head.sha` for PRs;
  both jobs are denied write permissions, and source policy cannot substitute
  for native guest execution. No new secrets are introduced.

## Remaining release blockers

1. Provision an independently authorized compiler build/runner; record SHA256,
   source revision, exact guest tree and nonzero runner-executed steps.
2. Execute the twelve fixtures and negative compiler tests in Java/Graal first;
   do not merge before actual guest execution.
3. Implement the native Workflow actor library and bounded durable state
   transitions, retries and compensation, cancellation receipts, tenant identity,
   authenticated approvals, idempotent outbox and store-enforced fencing.
4. Reconcile `graphs/*.json` with Oreslang source or replace them with
   generated native graph projections; until then the JSON is design only.
5. Add backend parity execution, not source-presence checks.

The developer shell scripts in this PR are *harness and policy*, never the
workflow execution semantics. Passing these shell checks alone is insufficient
for runtime acceptance.

- Added a native `WorkflowCoordinator` actor fixture to guard phase transitions, foreign fixed-run messages, duplicate starts and out-of-order completion. This is a non-durable state machine acceptance candidate, not an authenticated multi-tenant workflow runtime.

### Acceptance policy

1. Independent incident review must explicitly authorize cross-org source
   transfer before any Git-tree copy, however private the destination.
2. Compiler identity must be independently trusted and SHA-256 pinned; the
   demo's source sha must match its exact checkout; every native job must have
   real recorded steps, not only a completed run conclusion.
3. No JavaScript fallback, wrapper pretending to be a compiler, unverified
   fixture pass, or source-free canary may produce a green **native** verdict.
4. No merge or release on these grounds until compiler-backed actor/critical
   conformance is executed and reviewed.

### Canonical actor-state admission (additional blocking finding)

The previous patch attempted to create an ordinary method literally named
`handle_state` and a private field named `state`. That does **not** meet the
canonical sealed state-loan contract. To avoid confusing a simulated method
with compiler-owned authority, the source fixture now uses unambiguously
legacy names (`route_event` and `compatibility_phase`). The real
`state { ... }` and compiler-owned `handle_state` implementation is tracked
in upstream [issue #633](https://github.com/ores-truffle-oreslang/oreslang-source.java/issues/633),
[issue #1349](https://github.com/ores-truffle-oreslang/oreslang-source.java/issues/1349)
and [workflow issue #2236](https://github.com/ores-truffle-oreslang/oreslang-source.java/issues/2236).

**Do not mark canonical actor-state or critical-section conformance PASS**
using this compatibility fixture.
